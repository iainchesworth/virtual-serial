# Contributing

## Commit authorship

This repository has a single committer: its maintainer, **Iain Chesworth**
`<iain.chesworth@gmail.com>`. Every commit must be authored and committed with
that identity. Do not use `--author`, `GIT_AUTHOR_NAME` or
`GIT_AUTHOR_EMAIL` to attribute a commit to anyone or anything else.

Commit messages and files must contain no attribution beyond that authorship:

- no `Co-authored-by:`, `Signed-off-by:` or any other trailer;
- no "generated by", "generated with", "created by" or similar statements;
- no AI or tool attribution, and no robot markers;
- no `Author:` or `Committer:` lines in the message body.

The rule exists so the history stays exactly what the maintainer wrote and
approved. Two mechanisms enforce it:

1. `tools/check_commit_message.py` rejects offending messages. Enable the
   `commit-msg` hook once per clone:

   ```bash
   git config core.hooksPath .githooks
   chmod +x .githooks/commit-msg   # POSIX only; Git for Windows does not need it
   ```

   To check a message by hand:

   ```bash
   python tools/check_commit_message.py .git/COMMIT_EDITMSG
   python tools/check_commit_message.py --commit HEAD
   ```

2. The `Commit authorship` CI job checks every commit in a pull request or
   push, refuses attribution content, and refuses an author email that is not
   the maintainer's.

## Commit messages

```text
Short imperative subject, no trailing period

Why the change is needed and what it affects. Wrap the body at 72 columns.

Use the body to explain the reasoning, not to restate the diff.
```

Keep the subject at 72 characters or fewer. One logical change per commit
where practical.

## Pull requests

Run the checks locally before opening a pull request:

```bash
python tools/changelog.py --check
python -m unittest discover -s tools -p "test_*.py"
```

The pull request template asks for tests, a changelog fragment and
documentation updates. The `changelog.d/` workflow is described in
[`changelog.d/README.md`](changelog.d/README.md).
